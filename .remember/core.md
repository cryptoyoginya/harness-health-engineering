# Core — semantic invariant проекта

> Инвариант проекта (semantic memory). Коммитится в git.
> Здесь то, что **не меняется** от сессии к сессии: цель, контекст, hard rules.
> `now.md` и `today.md` — сессионные, gitignored.

## Цель проекта

Личный AI-харнесс по здоровью в духе Blueprint: markdown-репо = база знаний о теле и психике
(сон, восстановление, бады, нагрузка, активности, питание, социализация, ментальное). Цикл
Signal → Ingest → Synthesis → эксперимент → Feedback делает человека умнее о себе, а не просто
«попробовал». Whoop API автоматически приносит физиологию; субъективное вносит человек; ценность —
на стыке.

## Контекст

- Стейкхолдер: один человек, ведёт собственное здоровье как долгий проект.
- Объективные сигналы — Whoop (recovery, HRV, пульс покоя, сон, strain) через `scripts/whoop/sync.mjs`.
- Субъективные сигналы — настроение/энергия/тревога/соцконтакт, вносятся рукой в daily-лог.
- Полностью локально после первичной загрузки ONNX-модели (~120 MB при первом `kb:index`).

## Hard rules (нарушать нельзя)

1. **Медицинская граница:** агент не ставит диагнозы, не трактует симптомы как болезни; тревожный
   сигнал → врач/специалист.
2. **Красный recovery → лёгкий день**; gate тяжёлой тренировки recovery <50% → нет.
3. **Одна переменная за раз** в эксперименте.
4. **Метрики — прокси**, north-star субъективный («стало ли мне лучше жить»).
5. Русский во всех артефактах (ID/имена/термины — латиница).
6. ff-merge в `main`, без force-push; evidence/цитата + метка перед recommendation.
7. Значимые артефакты — сразу в git (`04_synthesis`/`05_decisions`/`06_outputs`).

## Карта слоёв

- `00_context/` — что это, роль Whoop, метрики, медицинская граница
- `01_raw/health/` — daily-логи (immutable evidence)
- `02_sources/health/` — недельные source-notes с метками
- `03_wiki/` — бейзлайны, реестр бадов, таксономия активностей
- `04_synthesis/` — паттерны недели, open questions
- `05_decisions/` — решения; `experiments/` — эксперименты
- `06_outputs/` — артефакты для людей
